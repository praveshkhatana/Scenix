## 2. Motion & focus language — the core consistency problem

There is ONE shared component (`core/Focus.kt`: ring / halo-glow / lift chosen by pack `focus.style`)
but **~10 ad-hoc focus implementations beside it**: nav buttons (BrowseActivity.kt:936-949,993-1001,1036-1047),
featured-slide marker (1751-1768, hard-coded `theme.id == "scenix-apple"` branch), detail season tabs
(DetailActivity.kt:610-626,826-831), hero play keyline (HeroComponent.kt:224-238), profile rings drawn
twice at different widths — 4 px (ProfilesActivity.kt:321) vs 3 px (ManageProfilesActivity.kt:314) —
inverted-plate keys in Search (:179-188) and ManageProfiles pickers (:761-777), PairingScreen bg-swap
(:210-215). Halo insets are per-screen magic numbers: 24/24/24/26/20/22/24/22/12/18/16 — none is a token.

Motion facts:
- `styles.xml:8` sets `windowAnimationStyle=@null`: **every screen-to-screen transition is a hard cut**.
  Only Profiles has an entrance (240 ms fade-up, :132-137); nothing else has one; nothing has an exit.
- `theme.json anim.*` tokens (`fadeUpMs 600, fadeUpShift 20, fadeUpStagger 30, screenFadeMs 180,
  cardFadeInMs 220, navFadeAt/Ms`) exist but **zero call sites read them**; `motionStyle` likewise unread.
- Durations actually used: 320 stage crossfade (`BrowseActivity.kt:509`), 500 trailer in (:685),
  instant trailer kill (:637-647), 900/900 skeleton pulse, 240/90 profiles, 140/140 game HUD — all
  hardcoded; the only interpolator in the codebase is AccelerateDecelerate (ease-in-out) where the
  motion law demands ease-out arrivals / ease-in departures.
- Player chrome show/hide is visibility-swap only over 3 538 lines (PlayerActivity.kt:2494-2546);
  modals in Settings/Addons appear with zero transition; ManageProfiles instead uses a platform Dialog
  (the ONLY animated modal). GameActivity fades its HUD 140 ms while CoiGameActivity toggles the same
  concept instantly.
- Two skeleton systems (Browse box-pulse vs Detail per-block legacy AlphaAnimation), one lone platform
  spinner (Player), and every setup screen uses bare "Reading…/Saving…" text where Browse/Detail paint
  skeletons. The 2500 ms "Saving" auto-clear constant is duplicated in 9 files.
- `core/Focus.kt:183-188` still animates translationZ though no call site enables it (dead perf trap).

**Rule to adopt:** one focus component with pack-driven style + ONE halo inset token; entrances =
fade-up via `anim.*`; sheet/modal motion via one shared helper; Player chrome and HUDs fade with the
same token family; window transitions restored as a themed fade (not the platform default slide).

## 3. Theme architecture vs the 5-pack requirement (owner 2026-11-01)

Target: **five packs with genuinely different layouts** — Apple (AppleTV), Netflix, PS5 (console-style;
motion ref https://v1.pinimg.com/videos/iht/hls/a2/43/d1/a243d128d38e78c3536a8cceeeb4d48c.m3u8),
Clean (light glass panels, centred pill nav, dual hero cards, category chips, poster grid —
`Downloads/clean-theme.jpg`), Kids (yellow, black pills, character cutout, chunky tiles —
`Downloads/kids-theme.jpg`).

What exists on games-mode (`assets/themes.json` manifest of 6 ids; picker in Settings):
- Pack JSON drives: `homeLayout/homeNavigation/homeHero/homeRails` enums (`HomeLayoutSpec.kt:87-95`),
  hero knobs, `rowStyle/cardStyle/focusStyle/detailStyle/navStyle` strings, ps5 geometry ints.
- But only **three Home surfaces are implemented**: HeroComponent (Apple), NetflixHeroComponent,
  Ps5HomeLayout — `HomeSurface.kt:60-101` factory branches on the Hero enum; `Family.ROKU_GRID/CLEAN/
  MAGNIFIER`, `Rails.GRID/LARGE`, `Hero.NONE` are declared and have **no consumers** — a `"clean"` pack
  silently renders Apple. Kids isn't even an enum value.
- Page skeleton is hardcoded in BrowseActivity (hero slot 0 + shelves stacked; order fixed).
- No third-party install path: packs are APK assets; the manifest is the allow-list; layout families
  are compiled Kotlin. A user theme today can recombine existing shapes only.
- Non-home screens bypass the layout contract (Detail/Search/Player are token-only; Settings has no
  pack branch at all; wordmark exists only on Browse/Profiles/PS5 rail).
- Web layer mirrors only token-level pack keys — PS5 hub / Netflix billboard have no web equivalent.

Gap list to ship the 5 packs: (1) implement a grid-rail renderer + Clean surface (centred top nav,
profile/bell cluster, dual hero cards, chip row, captioned grid); (2) Kids surface (cutout layer, pill
nav, big tiles) + `KIDS` enum; (3) make BrowseActivity consume the surface for the whole page instead
of fixing hero@0+shelves; (4) move the ~10 hand-painted focus chrome pieces into the pack vocabulary;
(5) if users must author themes, define a small layout schema (slots list) with a registry replacing
the `when` in HomeSurfaceFactory — until then state clearly that packs are curated, not installable.

## 6. Non-negotiables for anyone touching UI/UX

1. Branch from `games-mode`; never commit to main; one line of development.
2. Motion law (design/ui-tokens.md): animate only transform/opacity; duration families 120-160 /
   200-300 / 500-800 ms; exits faster than entries; ease-out in, ease-in out; infinite = loaders only;
   reduced-motion collapses to opacity. Read every number from `theme.json` — new numbers go there first.
3. One focus language per pack (halo for content tiles, thin ring for list rows, inverted plate ONLY
   where a keyboard needs keys lit). Halo inset/ring width = tokens, not magic numbers.
4. Eight-digit hex is banned in theme files; rgba() only (the token file rule); Kotlin fallbacks must
   match that form.
5. TV remote rules (settings pattern): whole-row focus stops, dial modal for values, in-place toggle
   for single booleans, actions modal for destructive verbs; add-ons are their own tab.
6. Say "IGC", never "illegal".
7. Verify on the windowed emulator (kill old instance with `adb emu kill` first) AND count logcat
   Daveys during a scripted key-walk — gfxinfo janky% is useless on the translated emulator; the real
   BRAVIA at 192.168.0.45:5555 is the perf target.
8. Hub rows go stale (`items:[]`) until re-warmed — re-curl before believing a bug.
9. Update this doc's findings into memory after fixing each class of issue.
